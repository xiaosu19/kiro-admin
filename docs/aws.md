# AWS 接入与常见错误

仅连接本人拥有或已获明确授权的账号。IAM Identity Center 支持直接创建用户和组，或连接既有身份源；背景见 [AWS 官方概览](https://docs.aws.amazon.com/singlesignon/latest/userguide/what-is.html)。Kiro 企业接入以 [官方企业文档](https://kiro.dev/docs/enterprise/concepts/) 为准。

## 接入信息

管理员在 AWS 账号页面配置访问凭据并验证，需要正确的 AWS 账号 ID、身份中心区域、订阅区域、Identity Store ID、实例 ARN、应用 ARN、Profile ARN 和门户登录地址。优先使用现有发现与验证入口，不要把其他母号或区域的 ARN 混用。

访问凭据必须允许实际需要的查询、用户 / 分组管理以及订阅操作。部分密码与订阅流程使用 AWS 控制台协议，可能随第三方更新而变化；项目的测试通过不代表任意 AWS 账号都具有对应功能或权限。请按所用功能授予必要权限，不把广泛管理权限作为排错的默认解决方案。

普通子用户只能操作已绑定母号内属于自己的记录。AWS 访问凭据及代理认证由管理员维护，不返回给子用户。

## 错误处理

| 提示 | 含义和处理 |
| --- | --- |
| `CreateAssignment: AccessDeniedException (HTTP 400)` | AWS 拒绝订阅写入。核对调用身份、IAM / 组织限制、区域、应用与 Profile 是否属于该账号，以及该账号的订阅资格；HTTP 400 本身不足以定位具体授权缺项。不要反复创建替代账号掩盖错误。 |
| `AWS 整体订阅缺失或重复，等待核对` | 订阅观察没有得到唯一且范围匹配的事实，可能涉及传播延迟、订阅来源或记录范围。保持待核对状态，刷新 AWS 事实并核对组 / 用户订阅，不能直接当作开通成功。 |
| 密码错误 / 锁定 / MFA 缺失 | 停止当前登录并明确报告。未知旧密码时，应由有权限的管理者明确重置；模型不处理 MFA。 |
| 代理不可用 | 检查母号绑定的代理及认证。系统不会静默切换为直连。 |
| 写入结果不明确 / 待核对 | AWS 可能已经执行。先只读核对实际资源和订阅，再决定恢复；不能按普通网络失败重复写入。 |

批次“失败”表示某个步骤未完成，并不自动撤销已创建的用户、组或订阅。仍有未处理开通意图、订阅或成员时，删除可能被阻止；使用停止、恢复、核对或级联删除入口处理，不要直接删数据库行。

## 授权和 JSON

登录流程与 AWS OIDC 结果分开判断。页面登录完成不等于 Token 已经取得；设备授权会按服务端间隔处理 pending、slow down、拒绝和过期。接口语义可参考 [AWS CreateToken 文档](https://docs.aws.amazon.com/singlesignon/latest/OIDCAPIReference/API_CreateToken.html)。

导出要求 Token、客户端信息、账号身份和区域能够相互对应，并通过目标格式校验。过期、缺失或归属不明确的结果不进入成功下载。当前实现主要面向 IAM Identity Center 企业账号；不保证 Builder ID、社交登录或未知 JSON 格式兼容，新增入口需独立适配和测试。
